# 按时长计组与计时提示音

本地增量，未上传、未提审。旧训练没有 `mode` / `durationSec` 时一律按次数处理，不迁移、不升 schema 版本。

## 行为

- 动作卡展开后可在「次数 | 时长」之间切换。时长组为可选重量（空 = 自重）+ 秒数（步进 5，1–3600）+「计时」+ 完成勾选。
- 「计时」复用组间歇倒计时，标题为动作名，结束显示「时间到」。走完后自动勾选该组，并开始组间歇。
- 手动勾选时，时长模式必须有 ≥1 秒（`DURATION_REQUIRED` / 「请输入时长」）；次数模式仍要次数。
- 切换模式保留已填的次数和时长。已勾选但缺少新模式数值的组会被取消勾选并提示，不会记成 0。
- 内置静态支撑（0463 前平板、0715 侧平板、1246 空心支撑、2135 负重前平板、3419 地面 L 型支撑）默认时长，其余默认次数。自定义动作可设「按次数 / 按时长」，加入训练时采用该默认。
- 容量只统计次数模式的正式完成组。累计时长只统计时长模式的正式完成组（热身、未完成不计）。只有计时组时不显示 0 kg 容量。
- 日历、训练详情、动作「我的最佳」按模式分别统计：次数取最重（并列次数多），时长取最长（并列更重）。
- 倒计时结束播放 `assets/audio/timer-end.mp3` 并 `wx.vibrateLong()`。设置里「结束提示音」默认开，关闭后仍振动，可试听。偏好为 `fit_ui_prefs.timerSound`。
- 结束事件比预计晚 3 秒以上（从后台或锁屏回来）不再补响、不补振，只更新倒计时状态；该组仍会自动勾选。
- 倒计时进行中 `wx.setKeepScreenOn`。音频失败被吞掉，不影响计时和存盘。

## 数据

| 位置 | 字段 | 说明 |
|---|---|---|
| WorkoutExercise | `mode: 'reps' \| 'time'` | 缺省 reps |
| WorkoutSet | `durationSec` | 整数秒 1–3600，或 null |
| 训练头 | `timeSec` | `computeSummary` 重算；纯次数且头上没有该字段时，`healHeaders` 不因此改写 |
| 自定义动作 | `trackMode` | 缺省 reps |
| `fit_ui_prefs` | `timerSound` | 缺省 true |

错误码：`INVALID_DURATION`、`DURATION_REQUIRED`、`INVALID_MODE`。

## 真机风险

- iOS 静音键依赖 `wx.setInnerAudioOption({ obeyMuteSwitch: false })`，只对 iOS 有效。同时播放音乐时，基础库可能仍会打断音乐（`mixWithOther` 在默认扬声器策略下不一定生效）。
- Android 媒体音量为 0 时不响，只振动；振动效果因机型而异。
- 微信退后台或锁屏会挂起 JS。亮屏只能降低漏提示的概率。回到前台时若已超时超过 3 秒，不会补响。
- `setInnerAudioOption` / `setKeepScreenOn` 在过低基础库上可能不存在，已 try/catch。
- 提示音约 3.5KB，随主包（倒计时组件在主包）。上传前以开发者工具的代码包体积为准。
