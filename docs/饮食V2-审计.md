# 饮食 V2.0 P0 审计

审计对象是改版前的饮食模块（`pages/diet`、`utils/repo/diet.js`、`utils/diet-formula.js`）。结论先说：碳循环里低碳日热量高于中碳日，符合已经锁定的周占比公式，不是计算 bug。P0 缺的是今日页信息架构、餐次和营养快照，不是再造一套阶段快照。

数据仍只在本机三个键里：`fit_diet_plan`、`fit_diet_logs`、`fit_diet_foods`。没有后端、没有 `user_id`、没有埋点。

## 存储（改版前）

| 键 | 内容 | 改版时怎么用 |
|---|---|---|
| `fit_diet_plan` | 计划头 + `stages[]`。每段有 `startDate`、`refWeightKg`、渐降的碳蛋白脂，或碳循环的 `days.high/mid/low` 和 `weekPattern` | 原样沿用。某天的目标用「开始日 ≤ 该日」的最后一段，不按当前体重重算 |
| `fit_diet_logs` | 按日期一条。`entries[]` 为 `kind: 'quick'`（三大营养素，名称固定「快速记录」）或 `kind: 'food'`（名称、口径、重量、算出的克数） | 保留。补 `meal`、`snap`、`v: 2`。旧 `quick` 视为营养素记录 |
| `fit_diet_foods` | 自定义食物：名称、口径、每 100g 或每份的碳蛋白脂 | 搜索和选择继续用。历史记录不回读这张表 |

缺键就是空状态，不是 0。读坏的键会停写，避免把损坏数据覆盖成空。

## P0 逐项（改版前）

1. **今日页。** 已有「今日 / 计划 / 复盘」三个平权顶栏，没有计划时先进计划页。今日页把目标和实际摄入分成两张卡，公式说明直接铺在今日。没有餐次卡片。可复用：日期前后切换、`dayTarget(date)`、`presentIntake`、`totals`。本次改成默认今日；计划和回顾收到导航右侧小图标，进二级页。
2. **记录饮食。** 「快速记录」会整日覆盖成一条 `quick`。「食物换算」是底部弹层，按 `每100g × 重量 / 100`（`scaleFood`）追加，生熟口径不能混用。两条路径不是同一个结构，也没有餐次。可复用：`addFood`、`scaleFood`、口径校验、自定义食物。本次两种模式都追加到同一天的 `entries`，并强制选餐次（默认按当前钟点：5:00–10:00 早餐，10:00–15:00 午餐，17:00–21:00 晚餐，其余加餐）。
3. **编辑和删除。** 只能移除单条、清空整天。不能改重量、营养素、餐次或日期。清空已有二次确认。可复用：`removeEntry`、`clearLog`。本次补 `updateEntry`。改食物重量只乘该条上的 `snap`，不读现在的食物表。单条删除要确认；清空当天在「⋯」里，再确认一次。
4. **文案。** 界面仍是「实际摄入 / 快速记录 / 食物换算 / 保存为这天的摄入 / 调整计划 / 复盘」。本次按新文案改用户可见字符串。存储里的旧名称「快速记录」只在迁移时清掉，不当成食物名。
5. **旧数据。** 没有迁移。`quick` 和 `food` 都能读，计划不会被摄入写入碰掉。本次 `migrateLogs`：只改 `fit_diet_logs`；`quick` 变成 `kind: 'nutrient'`、`meal: 'other'`、名称空；食物只补快照。同一份数据再跑一次不再写。写入失败时存储仍是旧值（单键 `set` 失败不会落下一半）；读回和预期不一致会把内存里的备份写回去。
6. **计划版本。** 已有阶段快照。改参考体重会从今天起 `commit` 新阶段，更早的日期仍用旧段的克数和热量。这次不重做这套机制，只加了一条回归：92 kg 内胚碳循环在 2026-10-17（周六、中碳）锁定 1584 kcal / 92 kg，次日改成 80 kg 后，17 日仍是 1584 / 92。

## 热量口径

截图「中碳 1584 / 高碳 2077 / 低碳 1987」对应：**参考体重 92 kg，内胚，蛋白 1.2 g/kg，碳水 2 g/kg，脂肪 0.8 g/kg**。低碳高于中碳是公式结果。

周碳 = 92 × 2 × 7 = 1288 g。周脂 = 92 × 0.8 × 7 = 515.2 g。蛋白每天都是 92 × 1.2 = 110.4 g，不按高中低拆开。

日克数 = 周总量 × 该日型的周占比 ÷ 该日型天数。占比是已确认的碳 50/35/15、脂 15/35/50，天数是高 2、中 3、低 2。

| 日型 | 碳水 | 脂肪 | 热量 |
|---|---|---|---|
| 高碳 | 1288 × 0.5 / 2 = 322 g | 515.2 × 0.15 / 2 = 38.64 → 38.6 g | round(4×322 + 4×110.4 + 9×38.6) = 2077 |
| 中碳 | 1288 × 0.35 / 3 = 150.266… → 150.3 g | 515.2 × 0.35 / 3 = 60.106… → 60.1 g | round(1583.7) = 1584 |
| 低碳 | 1288 × 0.15 / 2 = 96.6 g | 515.2 × 0.5 / 2 = 128.8 g | round(1987.2) = 1987 |

脂肪是 9 kcal/g。低碳日拿走周脂肪的一半，再分给 2 天；中碳日只拿 35%，还要除以 3。所以低碳日的脂肪热量压过它少掉的碳水，中碳日最低。`diet-formula.js` 写明不要为了把三天热量拉平去改克数。W=90、蛋白 1.0 的锚点（1960 / 1477 / 1872）也是中碳最低。单位是 g 和 kcal，系数是碳 4、蛋白 4、脂肪 9。克数先保留 1 位小数，热量再对这条式子四舍五入成整数。摄入汇总用同一套：把条目克数加总，再 `round(4C+4P+9F)`。目标和摄入的热量口径一致。

计划页点某一天的高 / 中 / 低，预览会马上重算，确认前不写存储。确认之后只从今天起新开一段。看过去的日期仍读那段快照，新的体重记录也不会改已经锁定的每日目标。

没有为这件事改公式。回归锁在 `tests/diet-formula.test.js` 和 `tests/repo.diet.test.js`。

## 本次沿用的计算和保存

- 渐降：Mifflin-St Jeor、活动系数、TDEE 减缺口、蛋白按体重或 532，`roundMacros`。
- 碳循环：`cyclePlan` / `roundMacros` / 一周必须 2 高 3 中 2 低。
- 食物：`scaleFood`，自定义食物口径锁定，口播例不能按「每份」记。
- 阶段：`commit` 只追加，`dayTarget` 按日期选段。
- 摄入：未记录不进平均的分母；`clearLog` 是删掉这天，不是写成 0。

首页不再放长篇公式。说明在饮食目标页的「计算规则说明」，完整推导仍在公式说明页。
