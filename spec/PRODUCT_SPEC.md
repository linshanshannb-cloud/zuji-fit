## 2. 核心流程

### F1 开始一次训练（今天）
1. P1 悬浮按钮（或选中今天时空状态里的「开始训练」）。
2. 已有草稿 → `showModal`「你有一个未完成的训练（10月15日 · 2 个动作）」，按钮 [继续] / [放弃并新建]。放弃 = 删除草稿（见 6.1），然后新建。
3. 新建草稿：`status=draft`、`date=今天`、`startedAt=now`，进入 P3。草稿在**第一次加入动作时**才写入存储（只开页面又关掉，不留下空草稿）。
4. P3 →「+ 动作」→ P4 多选 →「添加到训练」→ 回到 P3，新动作按选中顺序追加到末尾，每个动作自动带 1 个空组（重量和次数为 `null`）。
5. 录入组：调重量 / 次数 → 勾选完成。可以加组、删组、切换热身组、排序。
6. 「完成训练」→ 完成校验（3.3 R-C）→ `status=completed`，跳到 P2（`redirectTo`，返回直接回 P1），toast「训练已完成」。

### F2 补录过去的训练
- P1 选中过去日期 → 空状态 [补录训练]（或悬浮按钮）→ 新建草稿：`date=选中日`，`startedAt=null`，其余同 F1。
- 补录的组在加组时**默认 `done=true`**（补录就是已经练过的），用户也可以取消勾选。勾选时 `doneAt` 写当前时间（DATA_MODEL 没有区分补录，见第 9 节 #6）。

### F3 继续草稿
- P1 草稿横幅「继续」→ P3（加载草稿）。草稿没有过期时间。

### F4 查看、编辑、删除历史训练
- P1 摘要卡 → P2 →「编辑训练」→ P3（编辑模式：和草稿一样**改动即时保存**，与 API.md 的逐项写入一致；底部主按钮是「完成编辑」，点了以后只校验至少有 1 组已完成（不满足就提示「至少完成 1 组」并停留），不清理未勾选的动作和组，再回到 P2）。状态始终保持 `completed`。
- P2「删除」→ 二次确认（6.1）→ 删除后返回 P1，toast「已删除」。

### F5 从动作库加入当前训练
- P6「加入当前训练」：有草稿 → 追加到草稿末尾（带 1 个空组），toast「已加入当前训练 · 去查看」；没有草稿 → 新建**今天**的草稿并加入，然后跳到 P3。

### F6 记录 / 补录身体数据
- P7 悬浮按钮 → P8（日期默认今天）；P7 日历选中没有记录的过去日期 →「补录这天」→ P8（日期 = 选中日）。
- 保存 → 返回 P7，图表和日历刷新，toast「已保存」。

### F7 编辑 / 删除身体数据
- P7 记录行 / 日历卡片「编辑」→ P8 编辑模式 → 保存或删除（6.1 二次确认）。
- P7 记录行左滑「删除」→ 二次确认。

## 3. 每页交互规则

### P1 日历首页
- 默认显示本月，选中今天。左右滑或点箭头切月；「今天」按钮回到本月并选中今天。
- 月历只读取 `status=completed` 的训练。
  - 训练日：当天至少有 1 次已完成训练 → 强调色圆点。
  - 休息日：过去的日子里没有已完成训练 → 没有标记。
  - 选中日：黑色实心圆。
  - 今天：强调色数字。未来日期：浅灰数字。
- 选中日区块：
  - 有训练：每次训练一张摘要卡（名称或「M月D日训练」、`exerciseCount` / `setCount` / `volumeKg`，最多 3 个动作和它们的最佳组）。同一天有多次时按 `createdAt` 排序。
  - 有时长时显示「N 分钟」（`completedAt − startedAt`，补录的训练不显示）。
- 草稿横幅：存在草稿时，在任何选中日都显示；文案按草稿日期区分「今天 / M月D日」。
- 悬浮按钮：新建训练（日期 = 选中日）。选中未来日期时置灰，点击 toast「不能为未来日期新建训练」。
- 下拉不刷新；`onShow` 时重新读取存储（从 P3 / P2 返回后能看到最新数据）。

### P2 训练详情
- 只展示已完成的训练。动作按 `order`、组按 `index` 排序。
- 热身组：序号显示「热」，容量列显示「—」。
- 没打勾的组：整行变浅，容量列显示「未完成」，不计入统计。
- 动作找不到（`exerciseId` 不在库里）：显示 `nameSnapshot`，加 gray tag「未知动作」，动作名不可点。
- 底部：[删除] → 6.1；[编辑训练] → P3 编辑模式。

### P3 新建 / 编辑训练
**状态**：草稿模式（`status=draft`）/ 编辑模式（编辑一条 `completed`）。

**自动保存（两种模式都是）**：每次改动后 500ms 防抖写入存储，标题旁显示「已自动保存」；`onHide` / `onUnload` 时立即写入一次。写入失败按 7.1 处理。

**顶部**
- 「×」：草稿模式 → 直接返回（草稿已保存，P1 会显示横幅）；编辑模式 → 改动已保存，返回 P2（同样只校验至少 1 组已完成、不清理；不提供「放弃修改」，理由见第 9 节 #14）。
- 点日期打开「训练信息」面板：名称（≤30 字，占位「M月D日训练」）、日期（picker，`end`=今天）、备注（≤500 字）。改日期以后，横幅和日历都按新日期显示。

**动作卡**
- 新加入的动作展开，其余折叠；点折叠卡的标题展开。
- 「⋯」菜单（`showActionSheet`）：动作备注（≤200 字，写入 `WorkoutExercise.note`）/ 调整顺序 / 替换动作（进入 P4 单选，保留已录入的组，更新 `exerciseId` 和 `nameSnapshot`）/ 删除动作（撤销，6.2）。
- 排序：进入排序模式后，所有卡片折叠成行，拖动右侧把手；点「完成」退出。长按卡片标题 300ms 也能直接拖。松手后 `order` 重排为 0..n-1。

**组行**
- 序号：按 `index` 显示 1、2、3…；热身组显示「热」，**热身组不占正式组的序号**，显示序号只给正式组从 1 开始数；存储的 `index` 仍然连续包含热身组（见第 9 节 #4）。
- 点序号：在普通组和热身组之间切换（`type`），轻震动反馈。
- 步进器：重量 ±2.5、次数 ±1，长按连续加减；点数字弹出键盘直接输入。
- 完成勾选：`reps ≥ 1` 才能勾；`reps` 为空或 0 时点勾选 → 次数框抖动 + toast「先填写次数」。勾选写入 `done=true`、`doneAt=now`；取消勾选写回 `false` / `null`。
- 「+ 加一组」：新组复制上一组的 `weightKg` / `reps`，`type` 固定为 `normal`（调用 `addSet` 时显式传 `type:'normal'`，否则 API 会连热身类型一起复制），`done=false`（补录时为 `true`）。
- 删组：左滑组行露出「删除」，或长按组行 → 菜单「删除此组」。不弹确认，toast 撤销（6.2）。删除后 `index` 重排。
- 长按组行菜单：设为热身组 / 设为普通组、在下方复制一组、删除此组。

**底部操作栏（拇指区）**
- 草稿：[+ 动作] [完成训练]；编辑：[+ 动作] [完成编辑]。
- 「完成训练」在没有任何打勾的组时也可以点，点了以后按 R-C 提示原因（不做置灰，免得用户不知道为什么点不了）。

### P4 动作选择器
- 搜索：匹配 `nameZh` 和 `nameEn`（不区分大小写，去掉首尾空格），输入停止 300ms 后过滤。
- 筛选：肌群（`bodyPart`，6 项 + 全部）、器械（`equipment`，13 项 + 不限），都是单选；两个条件同时生效。显示名从 `data/filters.json` 读取，不在代码里写死。
- 列表点整行切换选中；「详情」→ P6（底部按钮为「选择这个动作」，点了以后勾上并返回 P4）。
- 已在当前训练里的动作显示「已添加」，仍然可以选。
- 底部「添加到训练 (N)」：N=0 时置灰。返回 P3 时保留选择顺序。
- 离开 P4 时不保留搜索和筛选条件（每次打开都是全部）。

### P5 动作库
- 默认按 `bodyPart` 分组（顺序按 filters.json），组内按 `id` 升序（与 data/ 保持一致；如果要按拼音排序，再和动作库管家对齐）。
- 搜索、筛选规则同 P4。顶部数量实时更新；有搜索或筛选时，分组标题显示组内的筛选结果数，没有结果的分组隐藏。
- 搜索和筛选条件在切 tab 后保留，冷启动后清空。
- 「清除」：同时清空搜索词和两个筛选条件。

### P6 动作详情
- 若动作带可选字段 `illustration`（试点 20）：详情顶区显示 1:1 线稿示意图；无字段或加载失败则回退文字占位块。列表页不显示示意图缩略图。细则见 `design/ILLUSTRATION.md`。
- 显示：`nameZh`、`nameEn`（首字母大写）、目标肌群 `target`、次要肌群 `secondary`（中文名查 `filters.json` 的 `muscles`；数据已合并同义词并去重，UI 不再处理）、部位 `bodyPart · bodyPartDetail`、器械、类别 `categoryZh`、步骤 `steps`。
- `translationPending=true`：步骤显示英文原文，标题旁加「暂无中文」标签。
- `description`：全部是英文原文（untranslatedFields 都包含它），v1 不显示。
- 「我的最佳」：所有已完成训练里，这个动作打勾的正式组中 `weightKg` 最大的一组（重量相同取次数多的），显示「60kg × 8」；没有时显示「—」。
- 底部按钮：F5；从 P4 进来时为「选择这个动作」。

### P7 身体数据
- 「图表 / 日历」分段，记住上次的选择（本地存储，key 与 Jarvis 对齐，例如 `fit_ui_body_view`；这是 UI 偏好，不属于 DATA_MODEL 的数据）。
- **图表视图**
  - 指标：体重 `weightKg`（kg）/ 体脂率 `bodyFatPct`（%）/ 腰围 `waistCm`（cm），默认体重。
  - 时间范围：近 30 天 / 近 90 天 / 全部，默认 30 天。范围按「今天往前 N−1 天」计算，包含今天。
  - 只取当前指标不为 `null` 的记录，按 `date` 升序连线。
  - 当前值 = 范围内最新的一条；「较上次」= 和它前一条有值的记录比较（可以在范围外），保留 1 位小数，带正负号；没有上一条时不显示。
  - 记录列表：显示当前指标最近 3 条（日期、数值、和上一条的差值）；「全部 ›」进入完整列表（复用同样的行样式，可以放在 P7 内展开，不单独做页面）。点击行 → P8 编辑；左滑 → 删除（6.1）。
- **日历视图**
  - 有记录的日期显示体重（体重为 `null` 时显示「•」）。
  - 默认选中今天；选中日有记录 → 三格卡片 +「编辑」；没有记录的过去日期 → [补录这天]；今天没有记录 → [记录今天]；未来日期 → 「还没到这一天」。
- 悬浮按钮 → P8（今天）。

### P8 新增 / 编辑身体数据
- 字段：日期、体重（必填）、体脂率（选填）、腰围（选填）、备注（选填，≤200 字）。单位固定为 kg / % / cm，不能切换。
- 日期 picker：`end` = 今天，不能选未来日期。
- 新增模式下，选了一个已有记录的日期 → 自动载入那条记录，切换为编辑模式，toast「已载入 M月D日 的记录」。
- 打开时自动聚焦体重。保存按钮常亮，点了以后再校验（3.3 R-B）。
- 编辑模式有改动时按返回 → `showModal`「放弃修改？」。

## 3.3 表单校验

所有数值输入：去掉首尾空格；只接受数字和一个小数点；保存时 `Math.round(x*10)/10`。校验在**失焦和点保存时**进行，输入过程中不报错。错误显示在对应输入框下方（红字），同时滚动到第一个错误的位置。

### R-A 训练组（P3）
| 字段 | 规则 | 提示 |
|---|---|---|
| `weightKg` | 空 = `null`；0–999.9；1 位小数。自重动作可以为空或 0 | 超出范围时自动夹到边界值，并 toast「重量最大 999.9 kg」 |
| `reps` | 空 = `null`；0–999 的整数；输入小数时截掉小数 | 「次数最大 999」 |
| 勾选完成 | `reps ≥ 1` | 「先填写次数」 |
| 名称 | ≤30 字，trim | 输入框 `maxlength=30` |
| 训练备注 / 动作备注 | ≤500 / ≤200 字 | `maxlength` 限制 |
| `date` | ≤ 今天 | picker `end` 限制 |

### R-B 身体数据（P8）
| 字段 | 规则 | 提示 |
|---|---|---|
| 体重 `weightKg` | **必填**；0 < x ≤ 700 | 空：「请填写体重」；超出范围：「请输入 0–700 kg 之间的数值」 |
| 体重合理性（软提示） | x < 20 或 x > 300 | 保存时 `showModal`「体重 X kg 看起来不太常见，确定保存吗？」 |
| 体脂率 `bodyFatPct` | 选填；0 < x ≤ 100 | 「请输入 0–100 之间的数值」 |
| 腰围 `waistCm` | 选填；0 < x ≤ 300 | 「请输入 0–300 cm 之间的数值」 |
| 备注 | ≤200 字 | `maxlength` |
| `date` | ≤ 今天；每天最多一条 | picker 限制；同一天自动转编辑 |

> DATA_MODEL 的规则是「三项至少填一项」，产品要求「体重必填」更严格，两者兼容，但需要对齐，见第 9 节 #1。

### R-C 完成训练 / 保存已完成训练（P3）
按 DATA_MODEL 第 4 节的完成规则：
1. 没有任何 `done=true` 的组 → `showModal`「至少完成一组才能结束训练」（只有 [知道了]）。
2. 有动作没有任何打勾的组，或者有没打勾的组 → `showModal` 说明会发生什么：
   「有 2 个动作没有完成任何组，结束后将被移除；另有 3 组未打勾，会保留但不计入统计。」[返回检查] / [完成训练]
3. 全部打勾 → 直接完成，不弹窗。
4. 完成时设置 `completedAt`，重新计算 `exerciseCount` / `setCount` / `volumeKg`。
5. **编辑已完成训练（「完成编辑」或「×」返回）**：只执行第 1 条（至少 1 组已完成），不弹第 2 条提示，也不清理未勾选的动作和组；状态保持 `completed`，`completedAt` 不变，统计重新计算（与 DATA_MODEL §4 规则 3 一致，见第 9 节 #15）。

## 4. 空状态

| 位置 | 条件 | 文案 | 操作 |
|---|---|---|---|
| P1 选中日 | 过去日期，没有训练 | 这天没有训练 / 休息也是训练的一部分 | [补录训练] |
| P1 选中日 | 今天，没有训练 | 今天还没有训练 | [开始训练] |
| P1 选中日 | 未来日期 | 还没到这一天 | 无 |
| P1 整月 | 当月没有任何训练（新用户） | 这个月还没有训练 | [开始训练] |
| P3 | 草稿里没有动作 | 从动作库添加第一个动作 | [+ 添加动作] |
| P4 / P5 | 搜索或筛选没有结果 | 没有找到“xx” / 试试其他关键词，或清除筛选 | [清除筛选] |
| P6「我的最佳」 | 没有记录 | — | 无 |
| P7 图表 | 没有任何身体记录 | 记录第一次体重，开始看趋势 | [记录体重] |
| P7 图表 | 当前指标在范围内没有数据 | 近 30 天没有腰围记录 | [切换到全部]（「全部」也没有数据时显示 [去记录]） |
| P7 图表 | 只有 1 个点 | 只显示这个点和数值，下方小字「再记录一次就能看到趋势」 | 无 |
| P7 日历 | 选中没有记录的过去日期 / 今天 | 这天没有记录 | [补录这天] / [记录今天] |

## 5. 加载状态

- 数据全部来自本地存储并同步读取，一般不需要 loading。
- 动作库 284 条：第一次进入 P5 / P4 时，如果渲染超过 300ms，显示 6 行骨架（灰块）；列表分批渲染（每批 30 条，滚动到底部再加载下一批）。
- 图表：canvas 初始化之前用同样大小的空白区域占位，避免页面跳动。

## 6. 删除：确认还是撤销

原则：**可以轻松重新录入的小粒度数据，用撤销；整条记录，用二次确认。**

### 6.1 二次确认（`wx.showModal`，确认按钮红色「删除」）
| 对象 | 入口 | 弹窗文案 | 结果 |
|---|---|---|---|
| 已完成训练 | P2「删除」 | 删除这次训练？ / 10月15日 · 5 个动作 18 组，删除后无法恢复 | 删除头和详情 key（顺序按 DATA_MODEL 第 8 节），返回 P1，toast「已删除」 |
| 草稿（放弃） | F1「放弃并新建」；P3「⋯」→「放弃这次训练」 | 放弃这次训练？ / 已录入的 N 组将被删除 | 删除草稿 |
| 身体记录 | P8「删除这条记录」；P7 左滑「删除」 | 删除 10月14日 的记录？ / 体重、体脂率、腰围将一起删除 | 删除，返回 P7，toast「已删除」 |

### 6.2 撤销（toast 带「撤销」，5 秒）
| 对象 | 入口 | toast | 撤销 |
|---|---|---|---|
| 组 | P3 左滑 / 长按菜单 | 已删除第 3 组 | 原位置恢复（index 重排） |
| 训练中的动作 | P3「⋯」→ 删除动作 | 已移除 杠铃卧推（4 组） | 恢复动作和它的组，回到原来的 order |

- 撤销期间又执行了新的删除：前一个撤销失效，只保留最近一次。
- 删除会立即写入存储；撤销 = 重新插入（恢复原来的值、type、done、位置），再写一次。

## 7. 失败状态

### 7.1 写入失败（`setStorageSync` 抛异常，常见原因：超过 10MB 或单个 key 超过 1MB）
- 草稿自动保存失败：标题旁「已自动保存」换成红字「保存失败」，并 toast「保存失败：存储空间不足」+ [重试]。页面上的数据保留在内存里，**不清空、不跳转**。
- 主动保存失败（完成训练、保存记录、删除）：toast「保存失败，请重试」，停留在当前页，按钮恢复可点。
- 连续失败 2 次：`showModal`「手机存储空间不足，无法保存。请清理微信缓存后重试」。

### 7.2 读取失败 / 数据损坏
- 某个 key 读不出来或不是数组：页面主体显示「数据加载失败」+ [重新加载]，不覆盖、不清空原数据。
- 训练详情 key 缺失（只有头）：P2 显示头信息和「训练详情丢失」，允许删除这条训练。
- 引用的动作不存在：显示 `nameSnapshot` +「未知动作」，不报错、不删除（DATA_MODEL 第 1 节）。

### 7.3 只读模式（`fit_meta.schemaVersion` 大于代码版本）
- 所有页面顶部常驻浅灰提示条「数据来自更新的版本，请更新小程序后再编辑」。
- 悬浮按钮、「编辑」「删除」「加入当前训练」等写入入口置灰，点击时显示同样的提示。

### 7.4 动作库数据加载失败
- P5 / P4 显示「动作库加载失败」+ [重新加载]；P2 / P3 里已经添加的动作照常用 `nameSnapshot` 显示。

## 8. 文案与格式

- 日期：「10月17日 周六」；同一年内不显示年份，跨年时显示「2025年12月30日」。
- 重量：最多 1 位小数，整数不带「.0」（60 而不是 60.0）；容量加千分位（4,320）。
- 体重和围度保留 1 位小数（68.4 kg、78.0 cm）。
- 训练名称为空时显示「M月D日训练」，不写回存储。
- 统一用「训练」「动作」「组」「次数」「重量」「热身组」「草稿」「已完成」这几个词，不混用「锻炼」「练习」等。

## 9. 与 DATA_MODEL 不一致或需要对齐的地方

| # | 项 | DATA_MODEL | 本规格 / 设计 | 建议 |
|---|---|---|---|---|
| 1 | 身体数据必填项 | 三项至少填一项（weightKg 可以为 `null`） | 产品要求**体重必填** | UI 按体重必填做；DATA_MODEL 加注「UI 要求 weightKg 必填，存储层仍兼容 null（迁移数据可能没有体重）」 |
| 2 | 同一天再次保存 | 合并：留空的字段保留原值 | P8 选到已有日期会自动转为编辑；编辑时用户可能要**清空**某个可选字段（比如删掉腰围） | API.md 已区分：`saveBody` 合并、`updateBody` 显式覆盖（空值清成 null）。约定：P8 新增模式调 `saveBody`，编辑模式调 `updateBody`。DATA_MODEL 第 7 节规则 3 建议补一句「显式编辑除外」 |
| 3 | 体重上限 | 0 < x ≤ 700 | 硬性校验同 DATA_MODEL；另加 <20 / >300 的软提示 | 软提示只在 UI 层，不改存储规则，确认即可 |
| 4 | 组序号显示 | `index` 从 1 开始连续，包含热身组 | 显示时热身组为「热」，正式组从 1 开始单独计数 | 存储不变，只在显示层换算；DATA_MODEL 加一句说明 |
| 5 | 草稿何时写入 | 新建时就有 draft（示例里 exerciseCount=0 的草稿） | 第一次加入动作时才写入，避免留下空草稿 | 需要对齐；如果坚持新建就写入，那么 P3 退出时没有动作的草稿要自动删除 |
| 6 | 补录训练的组默认值 | `done` 默认 `false`；`doneAt` 打勾时写入当前时间 | 补录时新组默认 `done=true` | 确认是否允许；补录的 `doneAt` 建议写 `null` 或当前时间，二选一后写进 DATA_MODEL |
| 7 | 训练时长 | 只有 `startedAt` / `completedAt` | 显示「N 分钟」=差值；编辑历史训练后，`completedAt` 是否更新？ | 建议编辑历史训练时**不改** `completedAt`（否则时长会变），只改 `updatedAt` |
| 8 | UI 偏好 | 没有定义 | P7 记住「图表 / 日历」、P5 筛选在会话内保留 | 新增 key 如 `fit_ui_prefs`（不纳入 schema 迁移），或只放内存 |
| 9 | 同一天多次训练 | 允许（`fit_workouts` 同日按 createdAt 排） | P1 一天多张摘要卡，月历只打一个点 | 一致，确认即可 |
| 10 | 肌群枚举 | 最新版已合并同义词，`target` / `secondary` 共用 `filters.json` 的 `muscles` | 详情页直接显示 | 已一致。注意 `data/DATA_NOTES.md` 的枚举表还是合并前的旧值（pectorals、latissimus_dorsi 等），请动作库管家同步 |
| 11 | `description` | 必填，目前全部是英文 | v1 不显示 | 等有中文翻译后再显示 |
| 12 | 自定义动作 / `archived` | 3.2 可选功能 | v1 不做，界面上没有入口 | 确认 v1 不做 |
| 13 | 动作库排序 | 没有规定 | 按 bodyPart 分组，组内按 id 升序 | 和动作库管家确认是否需要排序字段（比如常用度） |
| 14 | 编辑已完成训练 | 没有事务 / 批量保存；API.md 的每个修改都即时写入 | 编辑模式改为即时保存，不提供「放弃修改」 | 如果要支持「放弃修改」，需要 API 提供快照恢复（例如 `snapshotWorkout` / `restoreWorkout`） |
| 15 | 编辑已完成训练后的清理 | 完成规则（删除没有打勾组的动作、至少一组）只写在 draft → completed；`completeWorkout` 只接受草稿 | **已定（Jarvis）**：编辑后不重新清理未勾选的动作和组，只要求至少有 1 组已完成，与 DATA_MODEL §4 规则 3 一致 | 不需要新增接口 |
| 16 | 器械显示名 | `leverage_machine` 显示为「固定器械」 | 线框和筛选面板按「固定器械」 | 已一致（`DATA_NOTES.md` 里还写着「杠杆器械」，以 filters.json 为准） |
